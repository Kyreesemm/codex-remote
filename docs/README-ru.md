## Информация о проекте

Codex Remote: это Telegram-бот, который предоставляет удалённый интерфейс к Codex CLI, запущенному на личном компьютере. Он может служить альтернативой официальному способу удалённого управления Codex, для которого требуется подписка OpenAI и официальное приложение ChatGPT. Приложение ChatGPT доступно не для всех операционных систем, включая Arch Linux. Проект предназначен для ситуаций, когда нужно запускать задачи разработки или управления системой со смартфона, отправлять Codex запросы и получать результаты без прямого доступа к терминалу компьютера. Он выступает в роли интеграционного слоя для уже установленного Codex CLI и не включает в себя сам Codex CLI и не заменяет его.

При использовании команды `/codex` бот запускает Codex CLI в безоконном режиме внутри псевдотерминала и передаёт вывод задачи в Telegram. Он показывает текущий статус, возвращает итоговый ответ, отображает время выполнения и расход токенов, а также позволяет продолжить тот же диалог Codex следующей задачей. Интерактивные запросы процесса можно подтверждать из Telegram с помощью кнопок или обычных сообщений.

Помимо Codex, бот предоставляет управляемый удалённый доступ к shell-командам. Можно менять и просматривать текущий каталог, выводить список файлов, выполнять команды Git и shell-команды, а также передавать обычный текстовый ввод запущенному процессу. У каждого администратора Telegram есть изолированная сессия со своим каталогом, состоянием процесса и диалогом Codex.

В проект также входят список разрешённых администраторов, журнал активности, выбор модели через конфигурационный файл Codex и управление пользовательским systemd-сервисом для проверки состояния или перезапуска бота. Проект рассчитан на личное или доверенное окружение, где требуется удалённый доступ к компьютеру через приватный интерфейс Telegram.

## Быстрый старт & Установка

### Требования

Основная поддерживаемая среда проекта: Linux с Python 3.12 или новее. Codex CLI необходимо установить и авторизовать отдельно, а команда `codex` должна быть доступна в окружении, где запускается бот. Для клонирования репозитория также понадобится Git.

Проект использует Unix-псевдотерминалы, `/bin/bash` и пользовательский systemd. Нативный запуск в Windows сейчас не поддерживается. Пользователям Windows рекомендуется использовать WSL2 с дистрибутивом Linux, например Ubuntu, и выполнять инструкции для Linux внутри WSL2. Codex CLI также должен быть установлен и доступен внутри этого окружения WSL2.

### Клонирование репозитория и установка зависимостей

```bash
git clone https://github.com/Kyreesemm/codex-remote.git
cd codex-remote
python3 -m venv venv
source venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

В Windows с WSL2 выполните те же команды в терминале WSL2. Каталог Windows доступен из WSL2 по пути вроде `/mnt/c/Users/YourName/projects`.

### Создание Telegram-бота

1. Откройте Telegram и начните диалог с [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot` и следуйте инструкциям для выбора имени и username бота.
3. Скопируйте токен, который выдаст BotFather. Он нужен для параметра `BOT_TOKEN` и должен храниться в секрете.
4. Узнайте свой числовой Telegram user ID, например с помощью [@userinfobot](https://t.me/userinfobot). Ботом смогут пользоваться только ID, указанные в `ALLOWED_ADMIN_IDS`.

### Настройка окружения

Создайте файл конфигурации из примера:

```bash
cp .env.example .env
```

Откройте `.env` и задайте как минимум следующие значения:

```dotenv
BOT_TOKEN=your_token_from_botfather
ALLOWED_ADMIN_IDS=123456789
INITIAL_CWD=/home/youruser/projects
CODEX_COMMAND=codex
SHELL_COMMAND=/bin/bash
```

В `ALLOWED_ADMIN_IDS` можно указать несколько Telegram user ID через запятую. `INITIAL_CWD` задаёт начальный каталог сессий. Если Codex CLI не находится в `PATH`, укажите полный путь в `CODEX_COMMAND`. В WSL2 используйте Linux-пути вроде `/mnt/c/Users/YourName/projects`, а не `C:\Users\YourName\projects`.

Не добавляйте `.env` в репозиторий и не передавайте его содержимое другим людям. В нём хранится токен Telegram-бота. Остальные параметры из `.env.example` управляют частотой обновления вывода, размером сообщений Telegram, логированием, конфигурацией Codex и другими настройками работы.

### Простой запуск через Python-файл

Для ручного запуска в Linux или WSL2 активируйте виртуальное окружение и запустите точку входа:

```bash
source venv/bin/activate
python bot_worker.py
```

Процесс останется привязанным к текущему терминалу. Для остановки нажмите `Ctrl+C`. Такой режим удобен для первого запуска, тестирования и поиска проблем. Бот автоматически загружает `.env` из каталога проекта.

Нативный запуск `python bot_worker.py` в Windows не считается поддерживаемым, поскольку проект зависит от Unix-поведения PTY и Unix shell. Используйте WSL2.

### Запуск как системная служба Linux

В репозитории есть файл `systemd/codex-remote.service`. В нём указаны примерные абсолютные пути, поэтому перед установкой измените `WorkingDirectory`, `ExecStart` и `EnvironmentFile` в соответствии с фактическим расположением клона.

```bash
mkdir -p ~/.config/systemd/user
cp systemd/codex-remote.service ~/.config/systemd/user/codex-remote.service
systemctl --user daemon-reload
systemctl --user enable --now codex-remote.service
```

Проверить службу и посмотреть её логи можно командами:

```bash
systemctl --user status codex-remote.service
journalctl --user -u codex-remote.service -f
```

Служба настроена на автоматический перезапуск после сбоя. Если бот должен работать после выхода из системы, при наличии соответствующих прав включите сохранение пользовательской службы командой `loginctl enable-linger "$USER"`. После этого команда `/service` сможет показывать состояние службы и запрашивать её перезапуск.

Пользовательский systemd является функцией Linux. В этом репозитории нет конфигурации службы Windows. В Windows запускайте проект внутри WSL2, а системную службу Linux настраивайте там только если в используемом дистрибутиве WSL2 включён systemd.

## План обновлений

В план обновлений проекта входят следующие направления:

- **Поддержка платформ**
  - Адаптация проекта для нативной работы в Windows.
  - Улучшение совместимости с большим количеством дистрибутивов Linux.
- **Интерфейс и команды бота**
  - Добавление английского языка в бота.
  - Добавление новых команд и возможностей.
- **Документация для кодовых агентов**
  - Описание процесса обновления бота кодовыми агентами во время его работы.
- **Модульная архитектура**
  - Создание системы модулей, которая позволит добавлять новые возможности без изменения основного кода бота.
